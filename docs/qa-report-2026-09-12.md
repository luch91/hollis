## Confirmed inconsistencies

### QA-001: successful case intake is presented as a service failure

Severity: high

The owner submitted a complete case-intake form with initial evidence. The UI remained on the intake route and the server recorded `ReviewServiceError: The review service could not complete the request.` Opening the workspace immediately afterward showed that the case, its verified evidence reference, its Hollis Case Reference, and its initial audit event had all been committed successfully.

Impact: an operator can reasonably retry a successful operation after being told it failed. The source reference provides an idempotency boundary, but the user-facing result is still incorrect and can undermine confidence in the record.

Required follow-up: trace the final failing request or post-success revalidation step and return a success state when the durable operation has completed. Preserve the existing idempotency behavior. The root cause was not established or changed during this pass.

### QA-002: organization profile save returned an internal error

Status: resolved on 2026-09-12

The owner selected Technology, Europe, and a syntactically valid HTTPS website, then submitted the organization profile form. The UI entered workspace recovery. The server reported `WorkspaceAdministrationError` with status 500 and code `internal_error`. A fresh request showed that none of the three values persisted.

Root cause: the guarded PostgreSQL function used output-column names that collided with unqualified table columns. PostgreSQL rejected the ambiguous references before the update could complete.

Correction: migration `0033_fix_workspace_profile_column_references` qualifies membership, workspace, and return columns. A focused integration test and an owner browser save-and-reload test now cover this path.

### QA-003: read-only auditor was offered a case-creation interface

Status: resolved on 2026-09-12

The auditor role has `workspace:read` and `reviews:read`, but not `reviews:create`. The auditor could nevertheless open `/app/review-cases/new` and complete the full case-intake form. Submission was correctly rejected and created no record, but the rejection was presented as the generic workspace-recovery page.

Correction: role capabilities now fail closed in the web application. Auditors can inspect cases, evidence metadata, review history, attestation records, and exports, but cannot open intake or see case, evidence, review, or attestation mutation controls. The API authorization check remains the final control.

### QA-004: clipboard behavior

Status: accepted on 2026-09-12

The isolated browser exercised the manual-copy fallback because clipboard permission was unavailable. The owner subsequently confirmed that the copy control works in a normal browser. No application change was required.
